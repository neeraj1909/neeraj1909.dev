Mira: Customer Service Voice Agent

A local customer-service prototype for fictional orders, appointment changes, and local handoff records. The default text/form path is deterministic; optional live voice paths are separate experiments.

View repository ↗

Architecture & decisions

I built a FastAPI service over local SQLite fixtures and a browser UI. The default workflow uses fixed commands and forms without a provider call; optional voice modes use browser WebRTC.

  1. Use customer-scoped order lookup for the selected fictional customer.
  2. Show an appointment proposal and require explicit confirmation before recording a change.
  3. Record handoff intent locally; no human agent is contacted.

Safety boundary — the fictional customer selector is not authentication. The demo is intended for loopback only and must not use real customer information.

Indic Research Agent

This project explores India- and Indic-language questions through public-source search and evidence-grounded synthesis.

View repository ↗

Architecture & decisions

I implemented this workflow across the Chainlit UI, LangGraph tool loop, typed query-kit search tool, and storage/cache services:

  1. Chainlit receives the question and streams progress and answer tokens.
  2. A LangGraph tool-calling loop invokes a typed public-search tool backed by query-kit.
  3. The model synthesizes from returned sources; PostgreSQL stores chat history and Redis caches normalized search/tool results.

Scope decision — this is a public-provider research assistant. It does not ingest or search a local document corpus. Keeping the search boundary explicit avoids implying retrieval over material the app has not indexed.

Explainable Agentic RAG

Document-grounded RAG evaluation needs the evidence, workflow, and verification steps to remain inspectable. This is my local prototype for exploring that problem.

View repository ↗

Architecture & decisions

I implemented the local-PDF workflows and shared service/contract path. Local PDFs are loaded, split into chunks with source metadata, indexed in memory, then passed through selectable two-step, agentic, single-graph, or multi-agent workflows. The shared service and canonical contracts keep CLI modes on a common response path; attribution carries source, page, rank, and selection details with the answer.

Design choice — compare multiple retrieval/orchestration paths through one service and response contract, so the evaluation runner can use the same mode adapters as the CLI.
